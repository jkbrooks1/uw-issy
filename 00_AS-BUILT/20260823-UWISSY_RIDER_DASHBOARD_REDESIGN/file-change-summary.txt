    Rebuild dashboard around rider decisions, fix pipeline drops and empty map
    
    Pipeline: classifyRouteRelevance/classifyRouteImpact now trust lane 06's
    real route_relevance.classification + matched_route_sections signal, and
    isClosureTypeEvent/deriveFreshnessState recognize any lane's real
    status:"closed"/"planned" as a long-running closure, not just lane 01's
    event_type:"trail_closure". This surfaces real active trail closures that
    were being silently dropped as stale. mapEventGeometry no longer discards
    known-segment events with geometry:"none" — it derives real LineString/
    Point geometry from the canonical route line so the map has something to
    plot. presentation-eligibility.ts's independent dashboard guard mirrors
    the same closure-status exemption so it doesn't re-exclude events the
    data layer already approved.
    
    UI: CurrentRouteState.astro (built earlier, never wired into the page) is
    now the top-of-page Route Status panel with rider vocabulary (CLEAR/
    CAUTION/MAJOR ISSUE/CLOSED/DATA STALE). Page order is now status summary
    -> map -> current issues -> closures/detours -> weather/air -> route
    impacts -> collapsed monitor health, moving lane architecture out of
    prime space. RouteMap.svelte uses the CyclOSM cycling base layer instead
    of a generic CARTO basemap. Event cards carry severity, current status,
    detour availability, and rider passability where the source data
    supports it. Removed the unapproved footer tagline.
